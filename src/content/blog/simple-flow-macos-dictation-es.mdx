Hace tiempo que dejé de usar el teclado el 100% del tiempo. Con mucha más frecuencia, simplemente dicto texto por voz, esperando una transcripción rápida y precisa.

Principalmente, esto es para interactuar con modelos de IA. Mi esposa incluso bromea diciendo que ahora hablo más con mi ordenador que con ella. Y honestamente, no le falta razón: creo firmemente que para que una IA entregue resultados sobresalientes, cuanto más contexto, matices y detalles en vivo le aportes, mejor será el resultado. Escribir todo eso a mano en el teclado es simplemente tedioso y lento.

Por eso necesitaba una herramienta de dictado por voz. No una app genérica, sino algo que funcionara exactamente como yo quería: mantener presionada una tecla (`Fn / Globe` en modo push-to-talk), soltar mis pensamientos, soltar la tecla y ver cómo el texto transcrito aparece de inmediato justo donde parpadea el cursor.

En macOS existen opciones excelentes. Probé varias alternativas y dos me parecieron realmente buenas.

## Cómo funciona Simple Flow

Yo mismo no escribí ni una sola línea de código en Swift para esta aplicación. Toda la arquitectura, el código y la compilación final fueron generados desde cero por **OpenAI Codex** en tan solo dos prompts.

A nivel general, el flujo de trabajo consta de cuatro pasos lógicos:

1. **Captura del atajo de teclado**: La app reside silenciosamente en la barra de menús y detecta globalmente la pulsación de la tecla `Fn` (Globe) en modo push-to-talk.
2. **Grabación de audio**: Mientras la tecla está presionada, el audio del micrófono del sistema se graba en un búfer temporal.
3. **Envío a la nube**: En el momento en que se suelta la tecla, el archivo de audio se envía de forma asíncrona a mi endpoint remoto con autorización mediante token.
4. **Inserción del resultado**: El texto transcrito se pega de inmediato en la ventana activa emulando pulsaciones sintéticas de `⌘V`.

## Desarrollo en 2 prompts con Codex

### Prompt 1: Lógica central y máquina de estados

En el primer prompt, describí el flujo con palabras sencillas: demonio en la barra de menú, captura de la tecla `Fn`, grabación de audio, petición HTTP a la API e inserción en el foco activo.

Codex seleccionó los frameworks nativos de macOS (`AVFoundation`, `ApplicationServices`, `CoreGraphics`) y construyó una máquina de estados pura y determinista para gestionar todo el ciclo de vida:

```swift
public enum DictationPhase: Equatable, Sendable {
    case idle
    case recording
    case transcribing
    case feedback(FeedbackKind)
}

public struct DictationStateMachine: Sendable {
    public private(set) var phase: DictationPhase = .idle

    public mutating func handle(_ event: DictationEvent) -> [DictationEffect] {
        switch (phase, event) {
        case (.idle, .hotkeyPressed):
            phase = .recording
            return [.captureFocus, .startAudio]

        case (.recording, .hotkeyReleased):
            phase = .transcribing
            return [.stopAndTranscribe]

        case (.recording, .escapePressed):
            phase = .idle
            return [.cancelAudio, .returnToIdle]

        case (.transcribing, .transcriptionInserted):
            phase = .feedback(.inserted)
            return []

        case (.transcribing, .failed(let message)):
            phase = .feedback(.error(message))
            return []

        default:
            return []
        }
    }
}
```

### Prompt 2: Interfaz de ajustes y compilación final

En el segundo prompt, pedí una interfaz de usuario completa:
- Indicador de estado en la barra de menús (`Ready` / `Recording`).
- Ventana nativa de ajustes: selección de micrófono, grabador de atajos de teclado personalizados, comprobación de permisos de macOS (Accesibilidad y Micrófono) e inicio automático al encender el Mac.
- Almacenamiento seguro del endpoint y token API en el Keychain del sistema.
- Script automatizado para compilar el paquete `.app` de producción.

Codex escribió toda la interfaz en SwiftUI/AppKit, compiló el proyecto Swift en la terminal y me entregó el ejecutable `SimpleFlow.app`.
